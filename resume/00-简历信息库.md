#### 贯穿全程：稳定性与质量（这部分单独成段，是「工程成熟度」的证明）

**a) 恒温器式内存控制器（解决执行节点 OOM）** ✅ 已核实

设计文档：`docs/详解-内存保护-工作流匹配-里程碑.md`（含完整四层模型与代码）

- 背景：执行机内存 15GB，多用户并发跑任务会打满，**真 OOM 会导致整机卡死连 SSH 都进不去**，
  重启后任务一起涌回 → 反复重启死循环。
- 信号源：`/pressure` 接口读 `/proc/meminfo` 的 **`MemAvailable`**（比"已用百分比"准，排除可回收缓存）
  + `/proc/pressure/memory` 的 **PSI `some avg10`**（比剩余内存更早感知 thrash）。
- 四层防线：**准入闸门 → 每用户控制器 → OOM 自动重启(+swap) → 重启恢复**。
- 控制手法（这是最出彩的部分，用了控制论而不是拍脑袋阈值）：
  以 `MemAvailable%` 为反馈量，通过 systemd **`MemoryHigh` 软限**逼网关回收而非杀进程；
  设**加限/解限双阈值构成迟滞带**、动作间**强制稳定等待**，抑制过冲与震荡；濒临 OOM 时批量紧急加限。
- 效果：消除了执行机因单用户占用过高导致的**整机不可用**。

> 💡 面试话术：「这本质上是个**带迟滞的负反馈控制器**，像空调恒温器。
> 单阈值会在临界点反复加限解限震荡，所以必须做迟滞带 + 稳定等待。」

四个刻意的设计决策，每条都能讲：
- **多账户**：N 个虚拟用户 = N 个**互相独立账号**（不同 uid/工作区），真实模拟多人并发，
  而非「一个账号打 N 次」——后者测不出 per-user 锁竞争。

### P4【简略项目】to3D —— 图文联合 3D 生成系统

**仓库**：`bal483836-ctrl/to3d`（公开）　**建议篇幅**：简历里 2-3 行

#### 规模事实（✅ 已核实）
- **36 个 py 文件 / 4,003 行**；FastAPI + WebSocket + three.js 前端
- **35 个测试函数 / 9 个测试文件**；CLAUDE.md 记载 `make test` 应 22 passed
- 有 GitHub Actions CI（测试 + Docker 构建冒烟）、Docker Compose、Makefile、VSCode 调试配置

#### 一句话（核心差异点，务必讲准）
基于混元 3D（Hunyuan3D）的**图文联合**生成：多视图图像 tokens（DINO/CLIP）与文字 tokens（CLIP text）
**拼接为同一条件序列**，经 CFG 双模态引导（`image_scale`/`text_scale`）**单次生成一份模型** ——
**不是**「图生一个 + 文生一个再比较」。

#### 核心机制：图文联合生成 → 六维一致性自检 → 定向修正闭环
- **六维自检**：器型 / 花纹 / 底部 / 高度 / 宽度 / 材质。
  几何维度**直接在网格上真实测量**（Chamfer/IoU、包围盒比例、底部形态、对称性），
  纹理材质维度基于纹理描述与文字约束评分。
- **冲突仲裁**：某维度有对应视角图 → 以图像为准；无图但文字明确 → 提高文字引导修正。
- **修正闭环**：调高对应维度文字引导后局部重生成，**有界迭代收敛（防发散，取历史最优）**。
- **适配器架构**：`mock`（无 GPU 也能产出真实网格，全链路可跑可测）/ `http`（自建 GPU）/
  `tencent`（腾讯云 API）三套适配器**接口完全一致**，编排、自检、前端均无需改动。
  → 💡 这条讲「可测试性设计」很好：Mock 不是假数据，是能产出真实网格的降级实现。
- 附 `dataset_tool/`：上传 3D 模型 → Blender 按 50 组参考相机参数渲染 Color/Depth/Normal/Mask + meta。

## 8. 面试弹药：每个项目准备一个「深挖问题」

| 项目 | 最可能被深挖的问题 | 你的答题锚点 |
|---|---|---|
| 量子链阶段二 | 「为什么不做内网部署的 Web 版，非要做桌面端？」 | 数据不出内网只是底线；桌面端还带来**任务在用户本机 WSL 执行**、无需为每个客户维护服务器、离线可用三个收益。反过来代价是分发与装机复杂度 —— 这正是我做一键装机链路的原因 |
| 量子链内存控制器 | 「为什么不直接设 `MemoryMax` 杀进程？」 | `MemoryMax` 是硬限，触发即 OOM kill，用户任务直接丢失；`MemoryHigh` 是软限，**逼进程回收而非杀死**，任务能活着变慢。这是「可用性优先于严格性」的取舍 |
| 量子链密钥池 | 「共享 Key 有什么问题？」 | 三条：无法定位泄露源、无法按人撤销、无法计量到人。池化后审计落到**用户/设备/密钥三元组** |
| 卡皮巴拉 | 「1000 并发是怎么得出来的？压过吗？」 | **诚实**：这是设计目标与容量规划（PgBouncer 参数按此设定），未做实测；真实压测经验在量子链的 loadtest 工具里 |
| 卡皮巴拉 WebGPU | 「为什么不直接调 API 做补全？」 | 幽灵文本要求**逐字符低延迟**，API 往返做不到；端侧还省 token、隐私不出端。降级路径是 JS n-gram |
| 医疗 NER | 「F1 没达到你自己定的目标，为什么？」 | 先框口径（零样本 vs 有监督 SOTA），再讲已做的改进（反思校验、KG 过滤、嵌套扩展），最后讲下一步 |
| 医疗 NER | 「怎么保证没有数据泄露？」 | test 全程不参与训练；按 **doc_id 分组划分** val；阈值搜索只用 dev |
| to3D | 「六维打分的参照从哪来？」 | 输入图像证据 + 文字约束规格，**仅用于打分，不作为第二个交付物** —— 这是与"图生一个文生一个再比较"的根本区别 |
| 通用 | 「这些代码里 AI 写了多少？」 | 见 §0.2，主动亮出来，把落点放在「问题定位 + 方案否决 + 安全审查是我的」 |
